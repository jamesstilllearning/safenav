Existing Project Architecture

How the app is built — stack, routing, state, Firebase, and entry flow

SAFENAV CAVITE is a Flutter application (SDK ^3.8.0) for campus navigation and emergency evacuation at the EARIST Cavite Campus. It is package safenav_cavite, version 1.0.0+1, using Material Design and Riverpod for state management with GoRouter for navigation.

C

Navigation and Map Infrastructure

Two parallel routing systems, map data loading, and the missing pixel→GPS transform

What exists (implemented)

ComponentStatusKey files
GPS-space Dijkstra router
NavigationService builds a NavNode/NavEdge graph from CampusPathway and CampusBuilding objects and runs Dijkstra over Haversine distances, with optional avoidEmergencyPaths and preferMainPaths weighting, building-entrance nodes, and nearest-node snapping.		 Implemented lib/src/features/navigation/data/services/navigation_service.dart
Turn-by-turn instructions
_generateInstructions emits start, continueStraight, turnLeft/Right, turnSlightLeft/Right, uturn, arrive, enterBuilding, exitBuilding, enterFloor, exitFloor, useElevator, useStairs classified from bearing deltas, each with distanceToNext and route geometry.		 Implemented lib/src/features/navigation/data/services/navigation_service.dart
Pixel-space BFS safety router
CampusGraphRouter runs BFS over CampusGraph using only GraphStatus.confirmed edges, requires endpoints to be routable (surveyed lat/lng + confirmed + routable flag), supports avoidStairs, never guesses or snaps to nearby nodes (throws UnroutableEndpointError); edge cost is metadata only and safety takes precedence over distance.		 Implemented lib/src/features/map/data/services/campus_graph_router.dart
Campus safety graph model
CampusGraph/GraphNode/GraphEdge where nodes live in image-pixel space (x_px/y_px); lat/lng nullable and populated only from a surveyed record, never derived from pixels. GraphStatus enum (unreviewed/assumed/inferred/confirmed); isRoutable getter; JSON serialization.		 Implemented lib/src/features/map/data/models/campus_graph.dart
Coordinate transformer library
CoordinateTransformer implements WGS84<->UTM Zone 51N<->Local Cartesian conversions, affine and projective transform computation (least squares / DLT), GCP-based calibration (calibrateFromGCPs), TransformAccuracy statistics, and Haversine distance/bearing. Standalone library, not wired into parser or routers.		 Implemented (library, unwired) lib/src/core/services/coordinate_transformer.dart
Map data loading
MapDataService loads campus boundary, buildings, pathways Firestore-first with GeoJSON fallback (campus_boundary.geojson, campus_buildings.geojson, campus_pathways.geojson); results cached; loadAllData runs all three in parallel.		 Implemented lib/src/features/map/data/services/map_data_service.dart
Campus graph draft asset loading
CampusGraphService loads and caches assets/data/campus_graph_draft.json from the Flutter asset bundle.		 Implemented lib/src/features/map/data/services/campus_graph_service.dart
Campus plan reference loading
CampusPlanReferenceService loads assets/data/campus_buildings.json into CampusPlanData.		 Implemented lib/src/features/map/data/services/campus_plan_reference_service.dart
Voice guidance
VoiceGuidanceService wraps flutter_tts with initialize/setLanguage/setSpeechRate/setVolume/setPitch, speakInstruction mapping NavigationInstruction types to speech text, speakRouteSummary, stop/dispose, and Result-typed failure classes.		 Implemented lib/src/features/navigation/data/services/voice_guidance_service.dart
Custom OSM tile provider + cache
CustomTileProvider serves OSM tiles from local z/x/y file cache with network fallback; TileDownloader with concurrency semaphore; TileCacheService with cache directory, getCachedTileLayer, cacheCampusTiles (default zoom 14–19), cache size, clear, cached-tile listing.		 Implemented lib/src/features/map/data/services/custom_tile_provider.dart; lib/src/features/map/data/services/tile_cache_service.dart
Haversine distance & bearing
Computed in NavigationService (_distance/_bearing) and equivalent static methods in CoordinateTransformer, both using WGS84 earth radius 6371000 m.		 Implemented lib/src/features/navigation/data/services/navigation_service.dart; lib/src/core/services/coordinate_transformer.dart

Gaps (highest priority first)

1

Pixel-to-GPS transform not applied (transform gap)

The two navigation systems run in parallel with no transform linking them: the BFS router uses image-pixel space (x_px/y_px) while the Dijkstra router uses GPS (LatLng). CampusMapParser.setReferencePoints() stores reference points but explicitly applies no pixel-to-GPS transform ("coordinates remain in image-pixel space until surveyed"). The CoordinateTransformer library exists but is not wired into the parser or either router, so graph pixel nodes cannot be projected onto the OSM map and live GPS position cannot be snapped to the pixel graph.

Critical finding: dual navigation systems, no bridge

The app maintains two independent, unconnected navigation systems: (1) a GPS-space Dijkstra router (NavigationService) over LatLng pathway graphs built from OSM GeoJSON/Firestore data, with Haversine distance/bearing and turn-by-turn instructions; and (2) a pixel-space BFS safety router (CampusGraphRouter) over CampusGraph nodes in image-pixel space (x_px/y_px) that only traverses GraphStatus.confirmed edges and requires surveyed+confirmed+routable endpoints. The missing pixel→GPS transform is the single most consequential infrastructure gap in the app — without it, live GPS position cannot be snapped to the surveyed safety graph and graph routes cannot be projected onto the OSM map.
